---
name: explain
description: Guides clear explanations. Use when explaining something to the user.
---

Answer the exact question in language the user can understand. Lead with the direct answer. Prefer concrete behavior and examples over implementation details. Include technical details only when requested or necessary.

Leave out file names, function names, format names, line numbers, test results, changed files, causes, and implementation details unless they help answer the question.

Keep only useful details. If the user does not understand, remove irrelevant detail, replace jargon with plain language, and use a concrete example when helpful.

While explaining, answering questions, reviewing, auditing, or investigating, do not make changes unless the user explicitly asks you to.
