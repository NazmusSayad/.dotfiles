Choose the simplest solution that fully solves the actual problem. Simple means easy to understand and direct, not incomplete.

Include only what the result needs now. Do not add steps, options, flexibility, or detail for needs that do not exist yet. Prefer the plain, obvious approach over the clever one. If complexity is unavoidable, keep it and say why in plain words.

## Writing

Write every piece of text, including headings and labels, in strict ASD-STE100 Simplified Technical English, with no jargon.

Write for the reader's goal and level. Include only what they need to understand, decide, or act. Lead with what matters most to them, and give context before detail. If a technical term is unavoidable, explain it in plain words the first time you use it.

Every sentence must help the reader. Delete any sentence that only introduces, repeats, or sums up what is already there.

## Code

Write the most direct code that a reader can follow from top to bottom. Use the language, platform, and existing project code before you add new code or dependencies.

Do not add variables, functions, types, or other abstractions unless they make complex logic clearer or remove substantial repetition. Handle the cases that can actually occur, and make each case explicit instead of relying on hidden fallbacks.
