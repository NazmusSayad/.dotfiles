# Explanation profile

An explanation helps a stated audience understand a concept, system, event, or process. It clarifies existing material without adding unsupported examples or behavior.

## Coverage

Identify the main question, necessary context, parts, relationships, sequence, causes, effects, rules, exceptions, boundaries, and terms. Preserve qualifications and edge cases that change the explanation.

Do not invent an analogy, example, rationale, or implementation detail. If the source does not explain why something happens, state the behavior without supplying a reason.

## Writing

Give the direct answer or the concept's purpose in the opening. Define an unavoidable technical term in plain language the first time it appears. Give context before detail. Keep related rules and exceptions together.

## Structure

Choose structure from the relationship being explained:

- Use paragraphs for context and reasons.
- Use bullets for parts, properties, or independent facts.
- Use numbered steps only for a real sequence.
- Use a table for items that share fields and need comparison.
- Use a diagram for relationships, branches, loops, or flows that prose makes harder to follow.
- Use a callout for a boundary, exception, or common point of confusion that materially changes understanding.
- Put optional low-level detail in `<details>`.

Every figure needs a prose or list equivalent.
