# Report profile

A report presents recorded findings, measurements, events, or status. It does not create new findings from incomplete source material.

## Coverage

Inventory the report subject, audience when stated, reporting period, scope, definitions, measurements, units, sample sizes, methods, comparisons, findings, status, causes, effects, sources, limits, and unresolved points. Preserve the evidence attached to each conclusion.

Do not infer a cause, trend, recommendation, or status that the source does not state. Do not turn correlation into cause. You may calculate proportional CSS widths to display supplied values, but do not present those display calculations as new findings.

## Writing

State the report's most important supplied result in the opening. Keep domain terms that carry exact meaning.

Separate observations, source conclusions, and unresolved questions when the distinction matters. State limitations close to the affected finding. Do not hide a caveat in optional details when it changes how the reader should interpret a result.

## Structure

Use `.meta` or `.brief` for stated period, scope, owner, version, or method. Show a small set of headline values with `.metrics` only when those values are central to the report.

Use tables when exact values or comparison across shared fields matters. Use charts when their visual pattern improves comparison, and retain the exact values in labels or a nearby table. Keep units, denominators, category definitions, and time ranges visible.

Use a timeline for dated events and status labels only for statuses supplied by the source. Put methods, detailed evidence, or long source lists in `<details>` only when the report remains accurate without opening them.

End with sources or notes only when the source material supports them. Do not add recommendations merely because reports commonly contain them.
