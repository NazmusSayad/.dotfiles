Repository labels

Labels describe the kind of work in an issue, the affected area, and whether the issue needs special attention.

  1. Use
  2. Label groups
  3. Naming rules
  4. Automation detail

Use

  • Give each issue one type label.
  • Add all area labels that apply.
  • Add an attention label only while its condition is true.

Label groups

GroupPurposeLabels
TypeIdentifies the kind of workbug, feature, maintenance
AreaIdentifies affected code or documentationarea/api, area/web, area/docs
AttentionIdentifies a condition that needs actionneeds-info, blocked, security-review

Priority is not a label.

The project board stores priority. Keeping it there prevents two different priority values on one issue.

Naming rules

  • Use lowercase words.
  • Join words with a hyphen.
  • Use a slash between a group and a value, as in area/web.
  • Do not put a team name in a label.

Automation detail

Labels applied from changed paths
  • A change under src/api/ adds area/api.
  • A change under src/web/ adds area/web.
  • A change under docs/ adds area/docs.
