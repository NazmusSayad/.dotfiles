How browser cache validation works

Cache validation lets a browser check whether a stored response is still current. The server can confirm the stored response without sending the response body again.

  1. Parts
  2. Request flow
  3. Results
  4. Important boundary

Parts

  • An ETag is a value that identifies one version of a response.
  • The browser stores the response body and its ETag.
  • The server compares the stored ETag with the ETag of the current response.

Request flow

  1. The browser sends the stored ETag in the If-None-Match request header.
  2. The server compares that value with the ETag of the current response.
  3. The server sends 304 Not Modified when the values match. The browser uses the stored body.
  4. The server sends 200 OK, the current body, and its ETag when the values do not match.

Important boundary

Validation and freshness are different.

A fresh stored response can be used without contacting the server. Validation starts when the browser must ask whether a stored response is still current.
